> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** provisional.
- **Prerequisite:** plan 1 (`2026-10-13-listener-and-rhythm.md`) is built and its Rhythm gate **passed**.
- Before starting, re-read plan 1's gate results in `docs/experiments.md`. If they moved anything (e.g. a switch to 5m bars, a different typical beat length), update the defaults below in this file and commit before writing code.

**Goal:** Turn the beat grid into measures, track a confidence-ranked list of candidate keys, learn a chord vocabulary from data, name the chords musically by how they behave, and pass the Vocabulary and Harmony gates.

**Architecture:**
- `musical/beatsync.py` re-times bar features into per-beat and per-measure rows.
- `musical/keys.py` finds candidate key centers from volume-at-price and tracks them with a causal Bayesian filter that keeps several keys alive with confidences.
- `musical/chords.py` learns a discrete vocabulary (k-means) over measure descriptors: listener hidden states plus key-relative position.
- `musical/naming.py` names each chord from its transition behavior (tonic, predominant, dominant, applied V/x chains, deceptive), with positional degrees I–VII, and reads each measure under every candidate key.
- Two gate scripts test the result against surrogates and chance.

**Tech Stack:** as plan 1, plus scikit-learn 1.9 (KMeans, adjusted_rand_score) and scipy (`linear_sum_assignment`, `binomtest`; already installed with sklearn).

**Spec:** `docs/superpowers/specs/2026-10-13-market-harmony-design.md` (Layer 2, gates 2–3)

## Global Constraints

- Everything from plan 1's Global Constraints still holds: causal, no data ≥ 2023-01-01, code style, pre-registration before any gate run, commit trailer.
- **A measure's row is stamped at its last bar** and becomes usable only after that bar closes. Nothing about measure m may use bars after m's last bar.
- **Key centers are prices.** Every key-relative quantity is expressed in ATR units of the measure's last bar.
- **Names come from behavior on train data (< 2021-01-01)**; gates evaluate on val (2021–2022). Behavior wins over position. Unsupported names stay empty.
- **Default hyperparameters** (tune only where a step says so, and only on val):
  - candidate keys `max_keys = 5`;
  - profile bin `0.25` ATR;
  - profile lookback `32` measures;
  - modulation probability `p_change = 0.05` per measure;
  - new-key prior `0.02`;
  - modulation confirmed after the new top key holds `4` measures;
  - vocabulary size `K ∈ {8, 12, 16, 24, 32}`;
  - behavior lookahead `L = 4` measures;
  - significance `p < 0.01`, min support `n ≥ 200` measures per chord.

## Review Focus

1. **Measures of very different lengths** (tempo drift; a meter change mid-session): aggregation must not assume a fixed bar count. Test in Task 1.
2. **A key center that falls outside the current price range** (old heavy volume far away after a trend): it must stay a candidate with decaying confidence, not crash or be dropped silently. Test in Task 2.
3. **All candidate keys collapsing to one price** (very tight range): de-duplicate centers closer than 0.5 ATR. Test in Task 2.
4. **A chord with too little support:** it gets no role name (empty), never a guessed one. Test in Task 4.
5. **Applied-chord cycles** (V/x whose target's target is itself): chain depth must terminate (cap 4) without infinite recursion. Test in Task 4.

### Task 2: Candidate keys with confidences

**Files:**
- Create: `musical/keys.py`
- Test: `tests/test_keys.py`

**Interfaces:**
- Consumes: `measure_frame` (Task 1); bars (for the volume-at-price profile).
- Produces:
  - `volume_profile(bars_window: pd.DataFrame, atr: float, bin_atr=0.25) -> pd.Series`. Volume by price bin, using typical price (h+l+c)/3 per bar; the index is bin center prices.
  - `profile_peaks(profile, max_keys=5, min_sep_atr=0.5, atr) -> list[float]`. Local maxima of the 3-bin-smoothed profile, largest first, de-duplicated within `min_sep_atr`.
  - `KeyTracker(max_keys=5, p_change=0.05, new_prior=0.02, sigma_atr=1.0)`, with `.update(measure_row, peaks, atr) -> list[tuple[float, float]]` returning (center, confidence) sorted desc, with confidences summing to 1.
  - `track_keys(bars, measures, lookback=32) -> pd.DataFrame`. One row per measure, with columns:
    - `key{i}_center`, `key{i}_conf` for i = 1..5 (NaN-padded);
    - `top_age` (measures since key1 changed);
    - `modulation` (bool, True on the measure where a new key1 has held 4 measures).

The filter algorithm (not determined by the tests). Per measure:
1. **Predict.** Each existing key keeps (1−p_change) of its mass. The p_change mass is spread evenly over the other keys and the newly seen peaks; a new peak starts at `new_prior`.
2. **Likelihood.** Volume-weighted mean over the measure's bars of exp(−d²/2σ²), where d = (typical price − center)/ATR, times the profile mass at the center normalized over candidates.
3. **Update and renormalize**, then merge centers within 0.5 ATR (summing mass) and keep the top `max_keys`.

The profile uses only bars in the last `lookback` measures, ending at the measure's last bar.

### Task 4: Naming chords by behavior, reading measures under each key

**Files:**
- Create: `musical/naming.py`
- Test: `tests/test_naming.py`

**Interfaces:**
- Consumes: the harmony dataset (Task 3; train split only for fitting).
- Produces:
  - `ROLES = ["tonic", "predominant", "dominant", "applied", "deceptive"]`
  - `name_chords(df_train, L=4, alpha=0.01, min_n=200) -> pd.DataFrame`, one row per chord, with columns:
    - `chord`, `n`;
    - `degree` (I–VII, from position);
    - `role` (in ROLES or "");
    - `target` (chord id, or -1);
    - `depth` (0 = plain; 1 = V/x; 2 = V/V/x; …, capped at 4);
    - `name` (e.g. "V", "V/V", "ii", "I", "V→vi"), `p_value`.
  - `save_names(names, path)` / `load_names(path)` write and read a plain CSV (`models/chord_names_{run}.csv`). `ChordVocab.save/.load` use `models/chord_vocab_{run}.npz` (centroids + standardization).
  - `read_measure(row, names, max_keys=5) -> list[dict]`, one dict per candidate key: `center`, `conf`, `degree`, `name`.
  - `degree_of(rel_pos_atr, span_atr) -> str` maps position within the key's span to 7 bins I..VII. The span is the train 5th–95th percentile of `rel_pos` for that ticker.

Behavior rules (each needs `n ≥ min_n` and a one-sided `binomtest` vs the matched base rate, p < alpha; otherwise the role stays ""):
- **Dominant:** P(price within 0.25 ATR of the then-current key1 center within L measures | chord, not at center) > the same rate for all chords at matched |distance| (decile-matched).
- **Tonic:** at center (|rel_pos| < 0.5) in ≥ 50% of its measures, **and** a dominant precedes it more than its base rate.
- **Predominant:** P(next measure's chord is a dominant) > the base rate of dominants.
- **Applied V/x:** a non-tonic x with P(x within L | chord) > base rate of x, and the chord's measures sit on the side of x's typical position (pull toward x). If x is itself dominant or applied, depth = 1 + depth(x), with a visited-set to stop cycles, cap 4.
- **Deceptive:** a chord whose predecessor is a dominant but which is not tonic, and after which the dominant's resolution rate drops below its base rate.
- **Degree** is positional only. The `name` uses role when present, else the degree. Behavior wins.

### Task 5: Vocabulary and Harmony gates

**Files:**
- Create: `scripts/harmony_gate.py`
- Modify: `docs/experiments.md`, `CLAUDE.md`

- [ ] **Step 1: Pre-register and commit** in `docs/experiments.md`, before any run.

  **Vocabulary gate** (val 2021–2022) passes only if all three hold:
  1. val `bigram_gain` (k from `select_k`) > 0 **and** ≥ 2× the gain of the same pipeline on clock-shuffled surrogate data.
  2. Over seeds {0, 1, 2}: mean pairwise adjusted Rand index of val assignments ≥ 0.5.
  3. After Hungarian matching of centroids across seeds, ≥ 70% of chords with a non-empty role keep the same role.

  **Harmony gate** (val, with names fit on train) passes only if both hold:
  1. Chords named dominant reach key1 within L = 4 measures more often than decile-distance-matched non-dominant chords: difference ≥ 5 percentage points and binomial p < 0.01.
  2. Applied chords reach their named target within L more often than the target's base rate: pooled, p < 0.01.

  Informational output:
  - the vocabulary table (names, n, degree);
  - modulation rate per ticker;
  - the most common 4-chord progressions per ticker (the "composer" habits).
